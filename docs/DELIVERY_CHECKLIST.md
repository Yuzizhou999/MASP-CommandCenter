# 灵枢交付检查表

## 自动检查

正式提交前在干净的 CommandCenter 提交上执行：

```powershell
.\scripts\delivery-check.ps1
```

以下项目必须全部通过：

- 后端测试和前端生产构建；
- `git diff --check`；
- `.env`、运行数据、报名材料和设计草稿未进入 Git；
- `engine.lock.json` 指定的 MASP 提交存在；
- 演示包不包含原 MASP 工作区的未提交修改；
- 应用清单和 MASP 清单的文件摘要一致；
- 生产模式识别锁定引擎并允许仿真；
- 无 DeepSeek 密钥时显示确定性降级；
- 最小场景离线仿真完成；
- 前端生产入口存在。

自动检查通过后，保留控制台输出和最终 ZIP 的 SHA-256，记录到内部交付台账。

## 人工复核

- 在与比赛现场一致的 Windows 和 Python 版本上重新解压、安装、启动；
- 按《演示操作手册》完整走通一次，并录制备用演示视频；
- 检查常用桌面分辨率下无文本遮挡、按钮越界或横向滚动；
- 核对异常注入、What-if、审批和审计的时间与运行编号能相互对应；
- 确认模型不可用、网络断开、端口占用时的降级流程；
- 清空测试密钥、个人路径、临时下载和不应外发的运行数据；
- 检查 ZIP 解压后的文件名、中文路径和脚本执行策略；
- 确认现场人员掌握启动、停止、换端口和重新解压恢复方法。

## 权益与材料

- 项目负责人确认 MASP、地图、场景和 SOP 的参赛使用权；
- 确认 DeepSeek API 的账号主体、服务条款和数据处理要求；
- 完成 Python、React、FastAPI、Fluent UI 等第三方依赖的许可证复核；
- 报名表、成果提交表、演示稿、视频和系统名称保持一致；
- 申报数据注明统计口径、仿真条件和来源，不将仿真提升写成生产收益；
- 对外包不携带 `.env`、API 密钥、个人信息、客户订单或生产日志；
- 最终 ZIP 和材料文件进入受控目录，记录交付人、时间、摘要和接收人。

## 最终留档

建议至少保留以下内容：

- CommandCenter 提交号与分支；
- `engine.lock.json` 和 MASP 提交号；
- 演示包文件名、大小和 SHA-256；
- 自动检查输出；
- 现场复核日期、电脑环境和问题记录；
- 权益确认、模型卡、数据卡和安全说明；
- 与最终提交一致的操作视频和演示讲稿。
