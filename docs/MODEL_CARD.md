# 模型卡

本系统包含两类职责不同的模型：业务大模型负责自然语言理解和故障解释，群车策略模型负责提出车辆与任务的优先级候选。两类模型均不能绕过 MASP 的确定性安全边界。

## 模型用途

默认外部模型为 DeepSeek `deepseek-chat`。模型承担调度意图解析和基于已提供证据的异常解释，不承担路径规划、资源预约、冲突检测、事件注入或设备控制。

模型输出还要经过确定性边界复核。任务站点、车型和封锁资源必须来自参数解析器，模型不得自行补齐或改写；恢复、取消、故障上报等高风险意图不在大模型可生成范围内。模型不可用、JSON 不合规、实体越界、证据虚构或动作越权时，系统使用确定性结果并保留降级标记。

允许输出的意图：

- `QUERY_STATUS`
- `EXPLAIN_DECISION`
- `CREATE_TASK`
- `BLOCK_RESOURCE`
- `GENERATE_REPORT`

输出必须通过 `DispatchIntent` Schema 校验，后端会覆盖模型返回的世界版本、请求人和环境字段。

异常解释输入只包含事故实体、`EV-*` 证据、确定性 findings 和该事件允许的动作。输出必须通过 `DiagnosisReport` Schema，并满足：

- 每条根因和建议至少引用一个真实存在的证据 ID；
- 受影响车辆和任务必须属于事故记录；
- 车辆故障只能建议等待恢复、隔离重派或安全停车；
- 工位停用只能建议等待恢复、暂停关联任务或持续安全封锁；
- 死锁只能引用 MASP 已生成的受控倒退方案，或建议保持安全停车；
- 所有建议必须为 R3、要求仿真和人工审批；
- 任一校验失败时整份报告降级，不部分采信。

## 调用方式

后端通过 OpenAI 兼容的 `/chat/completions` 接口调用 DeepSeek。请求使用 `temperature=0` 和 JSON 输出模式。API 密钥只保存在服务端环境变量中。

## 降级策略

以下情况自动降级到本地确定性解析器：

- 未配置 `DEEPSEEK_API_KEY`；
- 网络错误、超时或非成功状态码；
- 返回体缺少预期字段；
- 返回非 JSON；
- JSON 不符合 Pydantic Schema。

降级结果会在 API 的 `fallbackUsed`、模型名称、界面状态和审计日志中标注。

## 安全约束

- 模型提示词明确禁止生成路线、资源预约和解除安全停车；
- 所有节点和资源必须通过 MASP 拓扑校验；
- 模型不能修改 `environment`、`basedOnWorldRevision` 或 `requestedBy`；
- 模型不能绕过风险策略和审批；
- 任何建议执行前必须进入确定性校验和数字孪生。

## 已知限制

- 本地解析器只覆盖比赛核心中文表达，不是通用中文语义系统；
- 当前知识检索是本地关键词匹配，不含向量模型和重排序；
- 当前会话不做长期记忆；
- 省略站点、车型或封锁资源时，确定性参数解析器会进入澄清轮次；模型不会获得用默认实体补齐的权限；
- API 数据是否可用于外部模型处理，必须由企业数据合规制度确认。
- 当前缺少真实设备遥测，模型只能解释“控制器报告的故障”，不能确认物理部件最终根因；
- 当前 MASP 没有公开的中途车辆故障续跑 API，What-if 是同一源场景上的保守反事实分支，并在界面和证据文件中明确标注。
- `evals/model-safety-v1.json` 提供固定安全回归集。只有报告中的 `liveProviderEvaluated=true` 才表示本次包含成功的 DeepSeek API 返回；边界向量和确定性降级不等同于真实模型效果评测。
- 工位停用演示没有替代工位业务映射，因此只暂停关联任务，不自动改写任务起终点；
- 等待环使用 MASP 版本锁定的拓扑和预约快照重放，恢复执行前仍需接入现场定位、净空确认和版本复核。

## 评测建议

赛前建立至少 100 条脱敏评测集，覆盖意图分类、字段抽取、虚构 ID、提示词注入、审批绕过、敏感信息和模型不可用。指标至少包括意图准确率、字段完全匹配率、非法工具调用率、虚构资源拦截率和降级成功率。

## 群车策略模型

群车策略采用 MASP Actor-Critic/PPO 优先级网络。观测由候选车辆与任务特征、候选路径 token、资源关系、候选掩码和优先级等待时间组成，动作是冲突分量内候选顺序的合法排列。模型只读调度快照并提出一个或多个顺序，不写入车辆状态、路径或预约表。

比赛版本内置 `models/ppo-priority-v1.pt`，后端自动登记该 checkpoint，也允许部署人员通过环境变量替换；客户端不能提交文件路径。加载前校验 checkpoint 版本以及 `observation_version`、`action_mode`、`reward_version`、`priority_prefix_count` 等元数据。运行时记录模型 ID、版本、文件摘要、推理次数与耗时、学习候选数、采用数、规则降级和 guardian 覆盖次数。

学习候选与规则候选使用同一套 MASP 评估器。连续时间 SIPP、运动学约束和资源预约是硬约束，Top-K guardian 保留确定性拥堵候选并按统一业务评分选优。未配置权重、元数据不兼容、推理异常、超时、非法排列或候选不可行时，系统使用规则基线，并在 `agent-policy-evidence.json` 中记录原因。没有通过校验的 checkpoint 不得标记为已启用模型。

登记模型采用滚动规划状态采集、SIPP 枚举监督和 PPO 微调训练。固定种子训练共采集 525 个局部冲突样本，训练集使用 96 个样本，独立验证集使用 32 个样本；验证集优先级前缀匹配率为 56.25%，平均奖励相对确定性基线增加 0.39125。该离线结果只证明模型训练、加载和候选推理链路可复现，不据此宣称整体调度性能优于 Top-K。上线候选仍须逐次通过确定性安全校验，模型训练明细和 SHA-256 摘要见 `models/ppo-priority-v1.json`。

在 14 辆混合车型、中等任务负载、3 个固定种子的运行验证中，学习策略 3 个用例均完成，资源预约冲突为 0，平均完成任务数为 8、小时吞吐为 32。当前 CPU 环境有 1 个用例出现超过 1 秒的规划周期，因此严格安全门槛未通过；该结果作为后续推理时延与候选评估优化的基线保留，不作生产 SLA 或性能领先证明。
