# 模型卡

## 模型用途

默认外部模型为 DeepSeek `deepseek-chat`。模型承担调度意图解析和基于已提供证据的故障解释，不承担路径规划、资源预约、冲突检测、故障注入或车辆控制。

允许输出的意图：

- `QUERY_STATUS`
- `EXPLAIN_DECISION`
- `CREATE_TASK`
- `BLOCK_RESOURCE`
- `GENERATE_REPORT`

输出必须通过 `DispatchIntent` Schema 校验，后端会覆盖模型返回的世界版本、请求人和环境字段。

故障解释输入只包含事故实体、`EV-*` 证据、确定性 findings 和允许动作。输出必须通过 `DiagnosisReport` Schema，并满足：

- 每条根因和建议至少引用一个真实存在的证据 ID；
- 受影响车辆和任务必须属于事故记录；
- 只能建议 `WAIT_RECOVERY`、`ISOLATE_REASSIGN`、`SAFETY_STOP`；
- 所有建议必须为 R3、要求仿真和人工审批；
- 任一校验失败时整份报告降级，不部分采信。

## 调用方式

后端通过 OpenAI 兼容的 `/chat/completions` 接口调用 DeepSeek。请求使用 `temperature=0` 和 JSON 输出模式。API 密钥只保存在服务端环境变量中。

## 降级策略

以下情况自动降级到本地确定性解析器：

- 未配置 `DEEPSEEK_API_KEY`；
- 网络错误、超时或非成功状态码；
- 返回体缺少预期字段；
- 返回非 JSON；
- JSON 不符合 Pydantic Schema。

降级结果会在 API 的 `fallbackUsed`、模型名称、界面状态和审计日志中标注。

## 安全约束

- 模型提示词明确禁止生成路线、资源预约和解除安全停车；
- 所有节点和资源必须通过 MASP 拓扑校验；
- 模型不能修改 `environment`、`basedOnWorldRevision` 或 `requestedBy`；
- 模型不能绕过风险策略和审批；
- 任何建议执行前必须进入确定性校验和数字孪生。

## 已知限制

- 本地解析器只覆盖比赛核心中文表达，不是通用中文语义系统；
- 当前知识检索是本地关键词匹配，不含向量模型和重排序；
- 当前会话不做长期记忆；
- 模型可能误解省略信息，生产版本需要澄清轮次和必填字段交互；
- API 数据是否可用于外部模型处理，必须由企业数据合规制度确认。
- 当前缺少真实设备遥测，模型只能解释“控制器报告的故障”，不能确认物理部件最终根因；
- 当前 MASP 没有公开的中途车辆故障续跑 API，What-if 是同一源场景上的保守反事实分支，并在界面和证据文件中明确标注。

## 评测建议

赛前建立至少 100 条脱敏评测集，覆盖意图分类、字段抽取、虚构 ID、提示词注入、审批绕过、敏感信息和模型不可用。指标至少包括意图准确率、字段完全匹配率、非法工具调用率、虚构资源拦截率和降级成功率。
